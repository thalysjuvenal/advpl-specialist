O `advpl-specialist` nasceu como plugin do Claude Code, mas todo o conhecimento tecnico (as 19 skills) e as instrucoes de repositorio sao portaveis para outros agentes de IA: GitHub Copilot, Cursor, Gemini CLI, Codex e mais de 70 agentes suportados pelo `skills.sh`.

## Passo 1: Skills (qualquer agente)

Instale as 19 skills no seu agente de preferencia com um unico comando:

```bash
npx skills add thalysjuvenal/advpl-specialist
```

Esse comando instala as skills em Copilot CLI, Codex, Cursor, Gemini CLI, OpenCode e 70+ agentes compativeis com o `skills.sh`.

## Passo 2: Instrucoes de repositorio

Copie os arquivos de instrucoes para a raiz do seu repositorio Protheus:

- `AGENTS.md`
- `.github/copilot-instructions.md`
- `CLAUDE.md`

Esses arquivos concentram as convencoes ADVPL/TLPP, os padroes de nomenclatura e as regras de boas praticas que orientam o agente durante a geracao e revisao de codigo.

## Passo 3: Comandos (opcional)

Se quiser reproduzir os comandos do plugin (`/advpl-specialist:generate`, `/advpl-specialist:diagnose`, etc.) na sua plataforma, copie a pasta correspondente para o seu repositorio:

- `.github/prompts/` — GitHub Copilot (funciona no VS Code, Visual Studio e JetBrains; NAO funciona em github.com nem no coding agent)
- `.cursor/commands/` — Cursor
- `.gemini/commands/` — Gemini CLI

### Nota Codex

O Codex ja e coberto pelo `AGENTS.md` combinado com as skills instaladas via `npx skills add`. Os custom prompts do Codex estao deprecated; as skills passam a residir em `.agents/skills/` dentro do projeto.

### Nota de manutencao

Os comandos distribuidos em `.github/prompts/`, `.cursor/commands/` e `.gemini/commands/` sao gerados automaticamente a partir de `ai-commands/src/`, usando o compilador `scripts/build-ai-commands.mjs`. Nao edite essas saidas manualmente — qualquer ajuste deve ser feito na fonte e recompilado.

## Verificacao do fonte sem hooks

No Claude Code, os hooks do plugin rodam o lint a cada gravacao e convertem o encoding no fim do turno. As outras IAs nao tem hooks, entao as skills trazem scripts avulsos que o agente (ou voce) executa depois de gravar o fonte:

| Etapa | Script bash | Script PowerShell |
|---|---|---|
| Lint (regras ADV001 a ADV022) | `skills/advpl-code-review/scripts/advpl-lint.sh` | `skills/advpl-code-review/scripts/advpl-lint.ps1` |
| Encoding (UTF-8 para Windows-1252), por ultimo | `skills/advpl-code-generation/scripts/convert-encoding.sh` | `skills/advpl-code-generation/scripts/convert-encoding.ps1` |

```bash
# 1. Lint do arquivo inteiro; saida 1 significa erros a corrigir
bash skills/advpl-code-review/scripts/advpl-lint.sh --scope all src/FATA001.prw

# 2. Corrija os erros e rode o lint de novo ate nao haver erros

# 3. Por ultimo, converter para Windows-1252 (estrito por padrao; --translit troca caracteres incompativeis por ?)
bash skills/advpl-code-generation/scripts/convert-encoding.sh src/FATA001.prw

# Depois de converter, nao edite o fonte com ferramenta que assume UTF-8 (os acentos se corrompem).
# Para editar de novo: --to-utf8 volta o fonte para UTF-8; depois, repita os passos 1 a 3
bash skills/advpl-code-generation/scripts/convert-encoding.sh --to-utf8 src/FATA001.prw
```

```powershell
# Windows sem bash: lint primeiro, conversao por ultimo
pwsh -NoProfile -ExecutionPolicy Bypass -File skills/advpl-code-review/scripts/advpl-lint.ps1 --scope all .\src\FATA001.prw
pwsh -NoProfile -ExecutionPolicy Bypass -File skills/advpl-code-generation/scripts/convert-encoding.ps1 .\src\FATA001.prw
```

As skills `advpl-code-generation`, `advpl-refactoring`, `advpl-to-tlpp-migration`, `smartx-development` e `smartview-development` trazem a secao "After writing the source" com esse roteiro: rodar o lint, corrigir os erros ate zerar, avaliar os avisos, converter o encoding como ultimo passo, e nunca dizer que o codigo compilou, porque a compilacao e a validacao no TDS / extensao TOTVS do VS Code continuam pendentes. Falsos positivos podem ser suprimidos no `.advpl-specialist-ignore`. Detalhes das regras, das diretivas e do encoding em [Validacao](/docs/referencia/validacao).

O comando `/validate` tambem existe nas outras plataformas: ele e compilado a partir de `ai-commands/src/validate.md` e distribuido como `.github/prompts/validate.prompt.md`, `.cursor/commands/validate.md` e `.gemini/commands/validate.toml`. Ele roda o lint no arquivo inteiro e faz a passada semantica S1 a S6.
